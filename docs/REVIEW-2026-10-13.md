# MaiBot Deskpet v1.0.1 代码审查

审查日期：2026-10-13（Asia/Shanghai）。基线：本地 HEAD `e1683d8`，标签 `v1.0.1`。审查开始时工作区干净。

本次覆盖插件消息网关与卸载、WebSocket 协议、Electron 主进程/预加载 IPC、服务进程管理、语音输入与云桥、模型发现与预设持久化、打包配置、发布 CI 和现有测试。业务源码未修改。本报告针对上述本地基线；没有将本地打包文件视为线上 Release 文件的完整性证明。

## 主要结论

基础类型检查、构建与现有回归测试通过。服务进程所有权、并发启动、等待退出再重启、录音所有权、模型加载生命周期已有较多防护。仍发现 8 项应处理的问题：3 项 P1，5 项 P2。当前测试通过不能覆盖这些额外复现的边界。

P1 表示应优先进入修复版本；P2 表示特定异常或配置条件下影响功能/发布，需要安排修复。

## 1. [P1] 默认 WebSocket 接受不受信任的网页 Origin，并允许消息注入与接收广播

位置：plugin.py:48、142、170。

默认 auth_token 为空，serve() 没有配置 origins 或等效握手校验。监听 127.0.0.1 限制了网络访问目标，但没有验证浏览器页面来源。任何能够访问该本机端口的客户端都可登记进入 _clients、提交 input:text / input:screenshot / sys:controls，并接收广播回复。具有本机网络访问能力的外部网页也可能通过这条路径访问；浏览器额外的本机网络权限策略会影响具体页面能否访问，服务端本身没有建立这层边界。

实际验证：使用真实 websockets 16.0，在随机 loopback 端口运行真实 DeskpetWSServer，以 Origin=https://untrusted.example 建立连接。服务端成功返回 sys:env，并将一条测试消息送入假的网关（gatewayInputs=1）。未连接实际 MaiBot 或真实业务端口。

建议：对握手 Origin 建立适配打包版和开发版的明确允许列表；同时提供本机配对令牌，避免默认无认证。若允许跨设备访问，要求认证。相关回归应覆盖允许来源、拒绝来源、缺失 Origin 和认证失败。

## 2. [P1] 百炼 TTS 把含音频 URL 的 JSON 当成 WAV 返回

位置：cloud-tts-bridge.py:42、176–192、279。

cosyvoice 分支使用 Qwen 风格的默认模型，但 _synthesize_cosyvoice() 对 HTTP 响应直接 resp.read()，没有处理返回 JSON 中的音频下载地址。后续 handle_tts() 无条件把结果标为 audio/wav。插件再对这些 JSON 字节做 base64，前端会按音频播放，表现为合成请求成功但无声音/播放失败。CosyVoice 与 Qwen 的模型、端点和响应契约也需要分开校准。

实际验证：用官方 Qwen 非流式响应结构 output.audio.url 构造 HTTP 测试替身，运行真实桥函数，结果 responseContentType=audio/wav、returnedJsonAsAudio=true。该验证没有调用收费 API。直接读取的阿里云 Qwen TTS 官方文档说明，非流式响应中的 output.audio.url 是合成音频的下载地址。

建议：按所支持的提供商协议解析响应、下载音频，并验证返回的内容类型/音频头；让模型与端点归属明确。增加“JSON 音频 URL → 实际音频”和上游错误响应的契约测试。

官方核对页面：`https://www.alibabacloud.com/help/en/model-studio/qwen-tts`。

## 3. [P1] 发布 CI 可能掩盖单元测试失败

位置：.github/workflows/release.yml:30–36。

Windows 工作流将 npm test 和 npm run typecheck 作为两个连续的原生命令放在同一 run 步骤。PowerShell 对原生命令的非零退出码不会仅因 ErrorActionPreference=Stop 就中断；如果 npm test 失败而后面的 typecheck 成功，最后的 LASTEXITCODE 会成为 0，步骤可以继续进入打包发布。

实际验证：在 PowerShell 中设置 ErrorActionPreference=Stop，先运行退出码 7 的 Node 命令，再运行退出码 0 的命令，最终得到 first_command_exit=7、final_native_exit=0，整个执行返回成功。

建议：拆成独立 CI 步骤，或在每个 npm/npx 命令后立即检查 LASTEXITCODE 并退出。另应把现有 host、model-lifecycle、runtime-trust、plugin-lifecycle、watchdog 套件纳入发布检查；当前 npm test 仅包含 services/PTT/voice-input/imageset 四个文件。

## 4. [P2] WebSocket 收尾没有超时，网关输入挂起可无限阻塞卸载

位置：plugin.py:149–151、273–289、643。

UNLOAD_TIMEOUT_SECONDS 只约束后台 TTS 取消和网关下线通知。最后 await server.stop() 仍会等待 wait_closed()。真实 websockets 的 wait_closed() 会等待连接处理器返回；如果处理器正在等待不返回的 gateway.route_message()，关闭连接不能结束这个等待。现有 bounded unload 测试使用立即返回的假 WS stop()，没有覆盖这条真实等待链。

实际验证：真实 WS 处理器进入一个受控挂起的假网关，将卸载超时设为 0.05 秒；启动卸载后 0.3 秒仍未完成。释放假网关后卸载立即完成。测试监听器与连接已清理。

建议：跟踪并取消入站处理任务，或使 route_message 等待可取消/有界，并给服务器收尾设置明确边界。回归必须包含真实连接处理器正在等待网关的情况。

## 5. [P2] 云端 STT 没有请求超时；取消 PTT 无法解除挂起状态

位置：deskpet-app/src/main/index.ts:1043、1104；deskpet-app/src/renderer/composables/usePttInput.ts:21、30–40、46。

云端两条 net.fetch() 路径没有 AbortSignal 或应用层超时。本地 HTTP STT 有 180 秒超时，云端路径没有同等边界。PTT finish() 在等待 options.stop() 前设置 stopping=true；cancel() 不会结束这次等待或清除 stopping。若自定义云端服务保持响应不结束，所有后续 onDown() 都被 stopping 拦住；取消、停止热键等动作也不能恢复下一轮录音。

实际验证：让真实 createPttController() 的 stop() 返回待决 Promise，执行开始、松开、cancel、再开始，startCount 仍为 1。释放转写 Promise 后才恢复。未访问麦克风。

建议：云端 STT 增加可配置的总超时与取消能力；PTT 停止/取消使用轮次标识，使旧请求的 finally 不影响新轮次，并让用户取消后可继续录音。补充永不返回、取消后重试与旧回复迟到的测试。

## 6. [P2] SignPath 参数使用产物名称，启用签名时会失败

位置：.github/workflows/release.yml:47–65。

上传步骤没有 step id，签名步骤 github-artifact-id 被填为 unsigned-installer。SignPath v1 官方 action.yml 要求这里传前一步 upload-artifact 的 outputs.artifact-id，而不是产物名称。SIGNPATH_ORGANIZATION_ID 配置后，该步骤会使用错误标识，正常的后续发布步骤也会被失败阻断。

核验：直接读取官方 v1 Action 定义，确认该参数的要求。本地已有安装器和 win-unpacked 主程序的 Authenticode 状态均为 NotSigned；未据此推断线上发布文件的签名状态。

建议：给上传步骤设置 id，并使用 `steps.<id>.outputs.artifact-id`。对未启用签名、签名成功、签名失败三种路径做工作流验收。

官方定义：`https://raw.githubusercontent.com/signpath/github-action-submit-signing-request/v1/action.yml`。

## 7. [P2] 模型 URL 未编码，合法目录名中的 # / % 会导致加载失败

位置：deskpet-app/src/main/index.ts:157–161、969。

scanModelFiles() 直接把文件相对路径拼接到 deskpet://models/ 或 ./models/。# 会被 URL 解析成 fragment；未编码的 % 会使协议处理器 decodeURIComponent() 抛 URIError。这些都是 Windows 允许的目录名，用户导入后虽能被扫描出来，却不能加载。

实际验证：从真实源码提取并执行 scanModelFiles()，目录 pet#1 产生 deskpet://models/pet#1/pet.model3.json，实际 pathname=/pet；目录 100%pet 的 URL 在解码时产生 URIError。

建议：生成 URL 时逐个路径段 encodeURIComponent，保持 / 分隔符；协议与文件解析按一致规则解码，并处理非法百分号编码。补充 #、%、中文、空格及路径往返测试。

## 8. [P2] 插件配置更新后，监听地址、鉴权与启用状态仍沿用旧值

位置：plugin.py:249–260、337–338。

on_config_update() 只输出 Config updated。WebSocket 服务器的 host/port/auth_token 是 on_load() 时复制的独立值，因此更新插件配置不会改变现有服务器。例如从空令牌改为非空令牌，当前服务器仍不要求认证；enabled 改为 false 也不会停止现有监听。

这是静态源码确认的行为；本次未操作真实 MaiBot 的配置界面，因此没有验证具体宿主版本是否会在此回调之外强制重载插件。

建议：在宿主只调用配置回调的情况下处理 enabled 与 WS 配置差异，必要时安全重建监听并关闭旧连接；如果设计要求重启宿主，应明确反馈“尚未生效，需重启”，避免仅输出已更新日志。

## 其他观察与改进建议

- 模型预设仍写到当前模型目录（main/index.ts:390），默认模型在安装资源目录中；写入失败返回 false，renderer/stores/deskpet.ts:330 却没有消费这个结果。只读安装目录会使磁盘同步静默失败。localStorage 仍保存一份缓存，因此不能笼统认定“所有预设都丢失”，但应把用户预设放入 userData，并明确展示持久化失败。
- 发布流程没有校验 tag、package.json 与 _manifest.json 的版本一致性，也直接 gh release upload 而不确保 Release 已存在。当前三个版本均为 1.0.1；这些属于下一次发版的流程改进，不证明本次发布失败。
- README 称默认云端硅基流动 STT，但 DEFAULT_CONFIG.sttBackend 为空，默认自启本地 STT。SETUP 仍有“尚未随新安装包发布”的解释器确认提示；GUIDE 的部分 TTS 端口/按句调度描述与代码不同。应以当前正式版行为重写首次安装与语音配置说明。
- SettingsPanel.vue、DeskpetStage.vue、services.ts 与主进程 index.ts 承担较多职责。后续适合拆出设置持久化、提供商协议、模型预设编辑和平台操作层；这是维护建议，没有把文件长度本身计为缺陷。
